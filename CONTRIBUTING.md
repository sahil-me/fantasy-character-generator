# Contribute to Fantasy Character Generator

Everyone is welcome to contribute, and we value every contribution. Code contributions are not the only way to support the project. Improving character generation, fantasy backstories, user interface design, accessibility, performance, character portraits, testing, or documentation are all valuable ways to contribute to **Fantasy Character Generator**.

This project was developed as part of a hands-on Google Skills learning experience. Contributions that improve the learning experience, maintainability, usability, and creative possibilities of the application are especially welcome.

If you find this project helpful, consider sharing it with others, referencing it in your blogs or projects, discussing it on social platforms, or simply giving the repository a ⭐️ to support the project and the community.

**However you choose to contribute, please be mindful and respect our [Code of Conduct](CODE_OF_CONDUCT.md).**

## Ways to contribute

There are several ways you can contribute to **Fantasy Character Generator**.

* **Character Generation Improvements:** Improve the character creation process, available character attributes, customization options, and the overall generation experience.
* **Fantasy Backstory Improvements:** Improve the quality, variety, consistency, and creativity of procedurally generated character backstories.
* **Character Customization:** Introduce useful customization options for fantasy characters, such as races, classes, character traits, backgrounds, or other supported attributes.
* **Character Portraits:** Improve existing character portraits, add suitable fantasy-themed artwork, and organize portrait assets consistently.
* **User Interface Improvements:** Improve the layout, visual hierarchy, responsiveness, navigation, and overall usability of the application.
* **React and TypeScript Improvements:** Improve component organization, type safety, state management, maintainability, and application structure.
* **Styling Improvements:** Improve Tailwind CSS usage, responsive layouts, visual consistency, typography, and styling conventions.
* **Accessibility:** Improve keyboard navigation, screen-reader compatibility, contrast, form labels, and other accessibility features.
* **Performance Optimization:** Improve rendering performance, asset loading, application responsiveness, and the efficiency of character generation.
* **Error Handling:** Improve validation, handling of invalid inputs, empty states, and recovery from unexpected application errors.
* **Security Improvements:** Help identify and address issues involving unsafe input handling, dependencies, configuration, and asset usage.
* **Testing:** Add or improve tests for character generation, backstory generation, UI components, input validation, and error handling.
* **Documentation:** Improve the README, setup instructions, project structure documentation, usage examples, troubleshooting guidance, and contribution instructions.

> All contributions are valuable to the project and its learning community. 🥰

## Submitting a bug-related issue or feature request

Feel free to open an issue when you encounter a bug or have an idea for improving **Fantasy Character Generator**. Include relevant error messages, reproduction steps, browser and operating system details, dependency versions, or screenshots when appropriate.

Please check the existing issues before creating a new one. This helps avoid duplicate reports and makes it easier to track existing problems.

### Did you find a bug?

**Fantasy Character Generator** becomes more reliable through community feedback, issue reporting, testing, and meaningful contributions.

Before reporting an issue, please make sure the bug has not already been reported under the repository's **Issues** section.

When submitting a bug report, please include the following information:

* Your **operating system** and version.
* Browser name and version, if the issue occurs in the browser.
* Node.js and npm versions, where relevant.
* Steps to reproduce the issue.
* A short description of the expected behavior and what actually happened.
* Relevant error messages from the browser console or terminal.
* The affected component, page, or character-generation feature.
* Relevant character attributes or input combinations that reproduce the issue.
* Screenshots or screen recordings, if applicable.
* Any other information that may help reproduce or understand the issue.

Please **do not include API keys, passwords, authentication tokens, `.env` files containing secrets, or other sensitive information** in an issue.

### Do you want a new feature?

If there is a new feature you'd like to see in **Fantasy Character Generator**, please open an issue and describe:

1. **Motivation**

   Explain the problem, limitation, or creative use case that the feature would address.

2. **Feature Description**

   Describe the proposed feature and how you would expect it to work.

3. **Character Generation**

   If the feature affects character creation, explain which attributes, customization options, or generation behaviors should change.

4. **Backstory Generation**

   If the feature affects generated narratives, describe the expected storytelling behavior, level of variety, tone, and consistency.

5. **User Interface**

   Explain how users should access the feature and how it should fit into the existing interface.

6. **Implementation Details**

   If you have an implementation idea, component design, or code example, feel free to include it.

7. **Additional References**

   If the feature is inspired by an external project, article, design, artwork, or technical reference, please include the relevant link.

A clear and well-written feature request makes it easier to evaluate and discuss the proposal.

## Do you want to improve character generation?

Character generation is a central part of **Fantasy Character Generator**.

You can contribute by:

* Improving the variety of generated character attributes.
* Improving the consistency of character descriptions.
* Introducing additional fantasy character options.
* Improving the combination of character attributes.
* Reducing repetitive or contradictory character details.
* Improving the handling of optional or missing inputs.
* Improving the balance between randomized and user-selected attributes.
* Improving the clarity and usefulness of generated character information.
* Adding tests for normal, boundary, and unusual input combinations.
* Improving documentation for the character-generation logic.

When modifying character-generation behavior, ensure that generated attributes remain consistent with the available options and that the application handles unexpected inputs gracefully.

## Do you want to improve fantasy backstories?

Fantasy backstories help make generated characters more distinctive and engaging.

You can contribute by:

* Improving the variety of procedurally generated backstories.
* Introducing additional narrative elements, motivations, and character histories.
* Improving the relationship between character attributes and their backstories.
* Reducing repetitive phrases and predictable narrative patterns.
* Improving grammatical consistency and readability.
* Improving the handling of different character combinations.
* Introducing additional narrative themes that fit the project's fantasy setting.
* Ensuring that backstories remain consistent with the generated character.
* Adding tests for different combinations of character attributes.
* Improving documentation of the backstory-generation logic and its limitations.

Changes should preserve the application's existing generation behavior unless a change is intentional. Test representative character combinations to ensure that new narrative elements work as expected.

> Backstory-generation improvements should be compatible with the project's existing implementation. Do not assume that an external generative AI service is used unless such integration has actually been implemented.

## Do you want to improve character portraits and assets?

Character portraits contribute to the visual identity of **Fantasy Character Generator**.

You can contribute by:

* Adding suitable fantasy character portraits.
* Improving the organization of portrait assets.
* Ensuring that asset filenames and paths are consistent.
* Improving the mapping between character options and portrait selection, where applicable.
* Handling missing or unavailable images gracefully.
* Optimizing image sizes and formats for web delivery.
* Improving image presentation across different screen sizes.
* Checking that images display correctly in the deployed application.
* Documenting the origin and licensing of newly introduced artwork.

When adding artwork, make sure you have the necessary rights or permission to use and redistribute it. Include appropriate attribution when required by the applicable license.

Avoid adding excessively large assets or unnecessary duplicate images.

You can contribute by:

* Improving the character creation form.
* Improving the layout and presentation of generated characters.
* Improving the visual hierarchy and readability of character information.

## Fixing outstanding issues

If you notice an existing issue and have a fix in mind, feel free to **[start contributing](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request)** and open a Pull Request.

### Making code changes

#### 1. Fork the repository

Go to the [Fantasy Character Generator repository](https://github.com/sahil-me/fantasy-character-generator) on GitHub and click the **Fork** button.

#### 2. Clone your forked repository

```bash
git clone https://github.com/<username>/fantasy-character-generator.git
```

```bash
cd fantasy-character-generator
```

#### 3. Create a new branch

Create a separate branch for your feature or bug fix.

```bash
git checkout -b feature/your-feature-name
```

For a bug fix, you can use a name such as:

```bash
git checkout -b fix/issue-description
```

#### 4. Set up the development environment

Make sure Node.js and npm are installed.

Check their versions:

```bash
node --version
npm --version
```

Use a Node.js version compatible with the project's dependencies.

#### 5. Install dependencies

From the project root, install the dependencies:

```bash
npm install
```

If the repository includes a `package-lock.json`, prefer the following command when setting up a clean development environment:

```bash
npm ci
```

Use the command appropriate to the repository's current dependency files. If installation fails, review the error and check the Node.js version and dependency compatibility before changing package versions.

#### 6. Review the project configuration

Before making changes, review the project's `README.md`, `package.json`, and relevant source files.

Identify the existing implementation of the feature you intend to modify.

If your changes require environment variables or external services, follow the project's documented configuration instructions.

> Never commit API keys, credentials, private configuration files, or other secrets to the repository.

#### 7. Run the application locally

Use the development command defined in `package.json`. For a project configured with the standard Vite development script, run:

```bash
npm run dev
```

Open the local address displayed in the terminal.

Verify that the application starts successfully and that the relevant functionality works before making changes.

If the development command differs in the current repository, follow the available project scripts.

#### 8. Make your changes

* Implement the feature or fix.
* Follow the existing project structure and coding conventions.
* Keep changes focused and maintainable.
* Avoid unrelated modifications.
* Preserve existing functionality unless a change is intentional.
* Keep React components readable and reusable.
* Use TypeScript types consistently.
* Document important assumptions.
* Test your changes before submitting a Pull Request.

#### 9. Test your changes

Run the checks supported by the project.

For a Vite-based project, the production build can typically be checked with:

```bash
npm run build
```

If the project defines a lint script, run:

```bash
npm run lint
```

Only run scripts that are defined in the current `package.json`.

Where applicable, test representative scenarios such as:

* Creating a character using typical inputs.
* Generating characters with different attribute combinations.
* Checking the generated backstory for consistency.
* Handling missing or unexpected inputs.
* Verifying that character portraits load correctly.
* Checking responsive layouts at different screen sizes.
* Confirming that existing functionality still works.
* Checking the browser console for relevant errors.
* Verifying that the production build completes successfully.

If automated tests are available, run the relevant tests and include the results in your Pull Request.

#### 10. Review your changes

Before committing, review the files you modified.

```bash

```

Check that your changes are intentional and that you have not included unrelated files, generated build output, local environment files, or sensitive information.

#### 11. Commit your changes

Stage only the intended changes.

```bash
git add <file-or-directory>
git commit -m "Describe your change"
```

Use a clear commit message that explains the purpose of the change.

#### 12. Push to your fork

```bash
git push origin feature/your-feature-name
```

Replace the branch name if you used a different one.

#### 13. Create a Pull Request

Open your fork on GitHub and create a Pull Request targeting the original **Fantasy Character Generator** repository.

* Explain what you changed.
* Explain why the change was needed.

If the project maintainer leaves comments or requests changes, address the feedback and push the required updates to your branch.

## Contribution Guidelines

To keep the project maintainable and welcoming:

* Keep Pull Requests focused on a single feature, fix, or improvement whenever possible.
* Avoid unnecessary changes to unrelated files.
* Follow the existing code style and project structure.
* Use TypeScript consistently with the existing implementation.
* Prefer reusable and maintainable React components.
* Test changes before submitting a Pull Request.
* Verify character-generation changes against representative examples.
* Check that generated backstories remain consistent with character attributes.
* Test UI changes at relevant screen sizes.
* Verify that portrait assets and other resources load correctly.
* Document assumptions that affect application behavior.
* Avoid introducing unnecessary dependencies.
* Do not commit API keys, `.env` files containing secrets, or other sensitive configuration.
* Respect the licenses and attribution requirements of third-party artwork and assets.
* Do not make unverified claims about external services or application capabilities.
* Provide clear commit messages and Pull Request descriptions.
* Include relevant screenshots, logs, or test results when appropriate.
* Be respectful and constructive when reviewing or discussing contributions.
